## SERV setup

The adapter uses `https://inference-api.openserv.ai/v1`, `SERV_REASONING_API_KEY` (with `SERV_API_KEY` as a legacy fallback), and `SERV_MODEL`. It sends the case fields to SERV only when the user requests an evidence plan. The local validator rejects refusal, truncation, invalid JSON, wrong capability and incomplete fields. A real structured-output request and full local case flow succeeded with `gpt-6-luna`; the request uses current SERV chat-completions parameters. Select a model from the [official model catalog](https://docs.openserv.ai/serv-reasoning/models) that is enabled for your account.

## Sirenic setup and payment boundary

The adapter constructs only `GET /v1/eu/entreprise/GB/{company_number}` or `GET /v1/entreprise/{siren}` for France. It reads `PAYMENT-REQUIRED`, accepts only Base USDC within Veyra's $0.05 ceiling, and stores the quoted amount, asset, network and recipient in the session metadata. The worker only allows these Sirenic paths and GET requests. A fresh quote is compared before execution, and one operation is reserved before sending the paid request.

The $0.005 quote was obtained without payment, then approved as a one-call session. One local and one hosted paid request returned HTTP 200 and a record matching the requested SIREN. Kite Passport activity associated each completed x402 payment with its session; read-only Base receipt checks confirmed successful transactions transferring exactly 5,000 USDC base units each. This verifies only the tested responses and settlement paths. It does not establish registry freshness for every company, source licence for every use, or service availability beyond these requests.

## Passport gate

Kite documents that an allowance can pay when no usable session is selected. Veyra creates a fresh separate session using `kpass session create --separate --no-reuse`, checks that the exact request/session pair is active, then passes the approved ID explicitly to `kpass session execute --session-id`. A mismatched ID was rejected before a provider request; one local and one hosted approved ID each completed a capped GET. Passport activity tied both payments to their sessions, and Base receipts confirmed settlement. The local `.env` and Vercel Production have `PASSPORT_LIVE_ENABLED=true` and `PASSPORT_SESSION_ONLY_VERIFIED=true`; the Vercel Sandbox automatically registers the hosted `veyra-buyer` identity if it is missing. A fresh, task-specific approval is still required for each paid operation.

The worker serializes operations, checks the request ID and active session ID immediately before the query, and caches results by idempotency key. If an execution becomes uncertain, Veyra blocks another attempt. After a successful query, the worker checks Kite activity for a completed x402 payment tied to the same session and returns its transaction reference when available. If activity cannot confirm it, the receipt remains `unknown` and must be checked before retrying.

## EasyPost gate

Test mode uses `EASYPOST_TEST_API_KEY`; live shipment mode uses `EASYPOST_PRODUCTION_API_KEY`. The keys are separate variables and the API response mode must match the requested mode. The response is reduced to status and a bounded set of tracking details. The test flow used EasyPost's official `EZ4000000004` USPS fixture and returned `delivered`; it made no production shipment or payment. EasyPost production account billing is separate from Kite. This adapter does not prove contents, condition, intended recipient or delivery claim truth.

## Vercel deployment mode

The public fixture demo and authenticated case API are deployed on Vercel. The production API uses the dedicated Supabase project instead of Vercel's ephemeral `/tmp` SQLite file. A hosted case completed the live SERV planning, session approval, explicit-session Sirenic query and receipt flow. The authenticated case page returned HTTP 200 with the same live case and review state.

The Vercel runtime uses `KITE_SANDBOX_NAME=veyra-passport-worker` to reach the named persistent Sandbox, not the local loopback URL/token. The signed-in CLI and registered `veyra-buyer` identity live in the sandbox's private home directory and are snapshotted for seven days; a fresh Kite login code is required for first-time setup or after the snapshot expires. Vercel Functions authenticate to Sandbox using the project's OIDC identity. The sandbox exposes no public port and auto-terminates sessions after five minutes. Production live gates are enabled after the hosted flow passed; Preview remains disabled. Sandbox usage counts against the account's Vercel Sandbox quota.

The same named Sandbox is the only hosted Passport worker. Keep its snapshots private and retain only the latest snapshot. Its Vercel Sandbox usage counts against the account quota.
